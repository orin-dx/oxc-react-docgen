Callisto already publishes native platform packages before the main/wrapper package, unconditionally, by category. Combined with SPEC-006 (native artifact placement into package dirs before publish — shipped this session) and fixed-group version alignment (platform + wrapper packages share one version via callisto.toml groups), callisto's existing machinery already does most of the 3-phase choreography agy is proposing to hand-build: version decision → artifact placement → ordered publish (platform first) is already how callisto publish works internally, in one pass.

So the real question for that repo isn't "does callisto support this ordering" — it does. It's: are the 10 platform packages actually configured as discoverable workspace members in the right fixed group, with napi.targets correctly declared so walk.rs classifies them as npm_platform_packages in the first place? If not, that's a callisto.toml/manifest-configuration gap in that repo, not a missing callisto feature — and the fix is much smaller than a custom CI build-matrix-plus-3-phase-workflow rewrite (still need the CI job that builds the N native binaries, that's unavoidable and outside callisto's job — but the placement/versioning/publish-ordering choreography around them is already callisto's job).
