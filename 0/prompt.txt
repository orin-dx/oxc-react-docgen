[CRITICAL] O(n²) JSDoc comment scan — crates/core/src/extractor/jsdoc.rs:18-23 (find_jsdoc) and :43-47 (extract_jsdoc_tags)
Evidence: `self.comments.iter().rev().find(|c| c.is_block && c.span_end <= span_start && span_start - c.span_end <= 120 && !self.consumed_jsdoc.contains(&c.span_end))`. `self.comments` holds every comment in the file; callers walk the AST top-to-bottom so span_start increases monotonically call-over-call. Each call has to skip every comment that lies *after* the current position before it can reach the one immediately before it — total work is O(n²) in comment count. Called for literally every prop, interface member, method, and component: extractor/mod.rs:501,516; interface.rs:43; visit.rs:122-123,173,228-229; component.rs:61-62,105-106,140-141,177-178,237.

N: 500 / 1000 / 2000 / 4000 / 8000 / 16000 / 32000
ms: 1 / 2 / 4 / 12 / 40 / 137 / 517
Ratio per doubling climbs 2x→2x→3x→3.3x→3.4x→3.8x, converging on the 4x a pure O(n²) predicts. This is a clean, unambiguous quadratic signature.

Fix: callers already visit in ascending span order — replace the `.rev().find()` scan with a monotonically-advancing cursor index into `comments` (or binary-search since spans are sorted), O(1) amortized instead of O(n) per call.
