## Comprehensive Report: React-Docgen &amp; React-Docgen-TypeScript Issues

### TOP 10 MOST PAINFUL ISSUES IN REACT-DOCGEN

1. **TypeScript Type Composition Failures** (#928, #914, #906)
   - Intersection types (`&amp;`) not supported when combined with unions
   - Parenthesized types (`(Type1 | Type2)`) fail to parse
   - Indexed access types (`Base["property"]`) don't resolve union elements
   - Workaround: None; users must restructure their types

2. **Utility Type Loss** (#925, #882)
   - `Pick&lt;&gt;` and `Omit&lt;&gt;` types return no props
   - `Extract&lt;&gt;` doesn't preserve union type information
   - Union types get stripped when wrapped in utility types
   - Impact: Common TypeScript patterns produce empty documentation

3. **ForwardRef Generic Type Extraction** (#927, #883)
   - `forwardRef&lt;RefType, PropsType&gt;()` generics ignored completely
   - Union types in props are lost with forwardRef
   - Requires redundant type annotation: `({prop}: PropsType, ref) =&gt;`
   - Estimated impact: ~30% of typed React components use forwardRef

4. **Monorepo Package Resolution** (#930)
   - Scoped packages (`@org/package`) in monorepos not resolved
   - Types imported from sibling packages missing entirely from docs
   - makeFsImporter.ts doesn't account for monorepo path structures
   - Breaks teams using workspaces; requires custom path resolution patches

5. **TypeScript .d.ts Files Ignored** (#929)
   - Type definitions from node_modules .d.ts files not parsed
   - makeFsImporter.ts only looks for .js files, ignores .d.ts
   - Common when using npm packages with TypeScript support
   - Workaround: None identified in issues

6. **Function Type Parsing Bug** (#994)
   - Function types in parentheses show as `"unknown"` instead of proper signature
   - Example: `(() =&gt; string) | undefined` → `{name: "unknown"}`
   - Specific to parenthesized function unions
   - Affects optional function props pattern

7. **Description Override Not Respected** (#997)
   - Extended interface property descriptions don't override parent descriptions
   - If `FooProps extends BarProps` and both document `param1`, parent description wins
   - JSDoc comments on overridden properties are ignored
   - Breaks documentation accuracy for interface hierarchies

8. **Flow Component Syntax Not Supported** (#944)
   - Flow's newer `component` keyword syntax causes crashes
   - Error: "Missing semicolon. (1:9)" at `component` keyword
   - Fails to extract props from Flow components
   - Only affects Flow users, but blocks Flow adoption

9. **Missing Babel Plugin Configuration Reuse** (#982)
   - Can't inherit Babel plugins from project config even with `configFile: true`
   - Pipeline operator syntax fails: "pipelineOperator plugin not passed options"
   - Affects projects using advanced JavaScript syntax
   - Workaround: Comment out typescript.reactDocgen in Storybook, loses type docs

10. **Components Returning Null** (#926)
    - Components that directly return `null` produce no interface
    - Affects boundary components, permission wrappers, early returns
    - Parser relies on analyzing return statements for prop extraction
    - Workaround: Force JSX return even for null-returning components
