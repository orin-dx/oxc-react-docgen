## Fix: JSDoc consumed-comment tracking (I7)

**Root cause confirmed:** `find_jsdoc` used a 120-byte proximity window with no deduplication. A JSDoc comment at the end of an interface (e.g., `/** Avatar diameter in pixels. */` before `size?: number`) was within 120 bytes of the following component declaration, so it was returned twice — once for the prop, once for the component description.

**Changes made (5 files):**

- **`extractor/mod.rs`**: Added `consumed_jsdoc: FxHashSet&lt;u32&gt;` field to `SourceDataCollector`, initialized in `new()`. Changed 8 method signatures from `&amp;self` to `&amp;mut self` due to the borrow-checker cascade: `ts_type_to_collected`, `ts_tuple_element_to_collected`, `ts_signature_to_object_field`, `extract_type_args`, `extract_type_name_from_type`, `extract_props_arg`, `collect_extends`, `collect_property_signature`.

- **`extractor/jsdoc.rs`**: `find_jsdoc` → `&amp;mut self`. Adds `!self.consumed_jsdoc.contains(&amp;c.span_end)` to the comment filter and inserts `span_end` on successful non-empty match. `extract_jsdoc_tags` intentionally left without consumed check — it is always called after `find_jsdoc` for the same span and needs to find the already-consumed comment.

- **`extractor/component.rs`**: 5 methods (`try_fc_annotation`, `extract_props_from_type_annotation`, `try_forward_ref`, `try_hoc_wrapped`, `try_forward_ref_exotic_decl`) changed to `&amp;mut self`.
