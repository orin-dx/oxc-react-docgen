## Rolldown Native Rust Plugin API — Research Report

### TL;DR

Yes, Rolldown has a native Rust `Plugin` trait. It lives in the dedicated `rolldown_plugin` crate (v1.1.1 on crates.io, released 2026-06-11). The full module path is `rolldown_plugin::Plugin`, also re-exported as `rolldown::plugin::Plugin`.

---

### Crate and module path

- **Crate**: `rolldown_plugin` — https://crates.io/crates/rolldown_plugin
- **docs.rs**: https://docs.rs/rolldown_plugin/latest/rolldown_plugin/trait.Plugin.html
- **Source** (GitHub): https://github.com/rolldown/rolldown/blob/main/crates/rolldown_plugin/src/plugin.rs
- **Crate directory in repo**: https://github.com/rolldown/rolldown/tree/main/crates/rolldown_plugin

Note: the repo moved from `rolldown-rs/rolldown` to `rolldown/rolldown`.

The `rolldown` umbrella crate re-exports the entire plugin crate:
```rust
// crates/rolldown/src/lib.rs
pub use rolldown_plugin as plugin;
```
So `rolldown::plugin::Plugin` and `rolldown_plugin::Plugin` are the same type.

### Trait definition (verbatim supertraits + required methods)

```rust
pub trait Plugin: Any + Debug + Send + Sync + 'static {
    // REQUIRED — no defaults
    fn name(&amp;self) -&gt; Cow&lt;'static, str&gt;;
    fn register_hook_usage(&amp;self) -&gt; HookUsage;

    // All other methods have default no-op async bodies (see below)
}
```

**Key design points (all adversarially verified):**
- Uses RPITIT (`impl Future&lt;Output = …&gt; + Send`) — NOT `#[async_trait]` on the trait itself. Requires Rust 1.75+.
- The crate does depend on `async-trait = "0.1.88"` (in Cargo.toml), but only for internal dyn-dispatch wrappers (`Pluginable`), not the user-facing `Plugin` trait.
- Not dyn-compatible directly; the internal `Pluginable` trait handles type erasure for the plugin driver.
- 44 total methods: 2 required, 42 with defaults.

### `transform_ast` — the OXC-native hook

Takes **owned** `EcmaAst` (confirmed from source):

```rust
pub struct HookTransformAstArgs&lt;'a&gt; {
    pub cwd: &amp;'a PathBuf,
    pub ast: EcmaAst,          // owned — direct AST manipulation
    pub id: &amp;'a str,
    pub stable_id: &amp;'a str,
    pub is_user_defined_entry: bool,
    pub module_type: &amp;'a ModuleType,
}
```

This is rolldown's extension beyond Rollup compatibility — lets plugins manipulate OXC's AST directly without a source → parse → generate round-trip.

### Internal architecture (not for plugin authors)

- `Pluginable` trait (in `pluginable.rs`): blanket-implemented for all `T: Plugin`. Provides `call_*` versions of each hook (e.g. `call_resolve_id`). The plugin driver operates on `dyn Pluginable` (type-erased).
- `SharedPluginable` = `Arc&lt;dyn Pluginable&gt;` — how plugins are stored and passed across threads.
- `PluginDriver` — orchestrates hook calls across the plugin list.
