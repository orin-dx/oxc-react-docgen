**1. Curated list — `crates/core/src/react_types.rs:104-155`**

`notable_html_attrs(element: &amp;str) -&gt; &amp;'static [&amp;'static str]` is a `match` keyed by **lowercase DOM element name** (`"button"`, `"input"`, `"a"`, `"textarea"`, `"select"`, `"form"`, `"img"`), each returning a hardcoded `&amp;'static [&amp;'static str]` of ~5-18 attr names (e.g. button: `onClick, onKeyDown, onKeyUp, onFocus, onBlur, disabled, type, form, name, value, tabIndex, aria-label, aria-describedby, aria-expanded, aria-pressed, aria-haspopup`). A `_ =&gt;` catch-all returns a generic 8-item fallback for any other element. There is no per-attribute type/metadata here beyond the name strings — types are inferred separately.

**2. Population — `crates/core/src/resolver/mod.rs:116-156`** (in `resolve_component`)

For each `InheritedLayer` in `chain.inheritance`: if `layer.html_element` is `Some`, it calls `react_types::notable_html_attrs(element)`, iterates the fixed name list, skips any name already in `props` (own prop wins) or already in `notable_inherited`, then **synthesizes** a `ParsedProp` via `html::infer_html_attr_prop_type(attr_name)` (a second hardcoded name→type heuristic in `resolver/html.rs`) with a fabricated `parent` pointing at `"{Element}HTMLAttributes"` / `node_modules/@types/react/index.d.ts`. For non-HTML layers, it instead copies real resolved props from `chain.inherited_by_name`. Note: this loop does **not** consult `layer.omitted` — an `Omit&lt;ButtonHTMLAttributes, 'onClick'&gt;` wouldn't currently suppress `onClick` from `notable_inherited` (pre-existing gap worth flagging when scoping).
