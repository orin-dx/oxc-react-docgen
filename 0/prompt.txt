    - `String`, `Number`, `Boolean`, `Null`, `Undefined`, `Any`, `Never`, `Unknown`, `Void`. Direct TS primitive keywords.
  - Literals:
    - `StringLiteral(String)`, `NumberLiteral(f64)`, `BoolLiteral(bool)`.
    - Non-finite numbers are encoded as the strings "NaN", "Infinity" and "-Infinity" (output.rs:470-486).
  - Composites:
    - `Union(Vec)`, `Intersection(Vec)`, `Array(Box)`, `Tuple(Vec)`.
    - `Object(Vec<ObjectField>)` is an inline object type with `{name, prop_type, required, description}` only.
  - `Named{name: CompactString, args}` is a name-only reference to an unexpanded type. It carries no file or symbol identity.
  - `ReactNode` is ReactNode, ReactElement, JSX.Element, ReactPortal, ReactFragment and ReactChild collapsed together (react.rs:19-23).
  - `CssProperties` covers CSSProperties and CSSObject.
  - `EventHandler{event_type: String, param_name}`:
    - Any single-parameter function type or `*Handler` name.
    - A zero-argument function has `event_type:"void"`.
    - It has no return-type field (func.rs:31-52).
  - `Ref{element: Option<String>}`.
  - `ElementType` is `React.ElementType`, used for polymorphic `as` and `component` props.
  - `HtmlAttributes{element, omitted}` is a marker for `ComponentPropsWithoutRef<'x'>`-style attribute inheritance.
  - `LiteralUnion{members: Vec<String>, has_default}` is a union of string literals from an alias, enum, const array, cva, or expanded template literal.
    - The same TS type inline is `Union[StringLiteral..]`.
  - `SxProps` is a name-based shortcut for MUI `SxProps`, `SystemStyleObject` and `SystemCssProperties` (known.rs:97).
  - `Opaque(OpaqueDetail{raw: String, reason})` is the give-up result.
  
  ### Variants with no natural checker-Type counterpart
  - **Opaque**: it carries only a raw string plus a reason, no structure. It is exactly where enrichment would replace a value.
  - **SxProps**: a name-matched marker, not a structural type. It also matches by name only.
  - **HtmlAttributes**: element metadata, not a type. The real expansion depends on `HtmlAttributeMode` (Curated, Full or None; pipeline/mod.rs:52-66).
  - **Named**: it has no symbol, declaration or file identity. Generic args are `PropType`.
  - **ReactNode, CssProperties, ElementType, Ref, EventHandler**: name-based collapses of declared React types.
    - `Ref` keeps only a string element.
    - `EventHandler` drops return type and any second parameter.
  - **LiteralUnion**: `members` are display strings. Numbers and booleans from enums are stringified via `to_display_string`, so type information is lost.
  - **Object**: no optional or readonly distinction beyond `required`, and no index signatures, call signatures, or method-versus-property distinction.
  - **Tuple**: elements only. There is no optional, rest or named-element info.
  - TS shapes with no variant:
    - bigint and symbol become `Named`.
    - Enum types: no variant.
    - Multi-parameter functions become Opaque(MultiParamFunction) (func.rs:55-80).
    - Readonly and unique operators are peeled by the extractor.
    - `undefined` inside a union is dropped by `resolve_union` (primitives.rs:19-21).
    - `typeof X` becomes `Named`.

  ## 4. Watch and incremental model
  
  Files: `crates/core/src/pipeline/watch.rs`, and `ReverseDeps` at `pipeline/mod.rs:143-187`.
  
  ### `update_file` flow (watch.rs:165-345)
  1. Canonicalize the path (`canonicalize_best_effort`, line 175).
  2. Read and re-parse only the changed file and cache it in `source_cache` (179-188). There is no DTS cache use here.
  3. `global.rcu`: deep-clone the entire `GlobalSourceData`, then `remove_file` and `merge` the new data (196-201).
  4. Patch `NamedTypeIndex` in place under a Mutex via `Arc::make_mut` (211-217).
  5. `affected = reverse_deps.load().affected(changed)` (220). This is a BFS over file-level reverse imports.
  6. `affected_mappings` = every `ComponentMapping` whose `m.file_path` is in `affected` (227-228).
  7. Build a fresh `ResolutionContext`, then `par_iter` with `contain_panic` per component (231-270).
  8. Evict `component_cache` entries with `file_path == changed`, unless the read failed (295-305).
  9. Insert results with a disambiguation check (307-329).
  10. Replace the per-file diagnostics entry (333-337).
  
  ### Dependency granularity
  - **There is no per-component input-file or dependency set.**
    - Selection is file-level.
    - `ResolveState.visited` and `named_in_progress` are discarded after `resolve_component`.
    - `PropParent.file_name` and `InheritedLayer.file_name` are output provenance, not used for invalidation.
  - `ReverseDeps::build` (pipeline/mod.rs:149-169):
    - It reads only `global.import_map` (line 152).
    - Only relative specifiers count (155).
    - It probes `.ts`, `.tsx`, `/index.ts` and `/index.tsx` by lexical `join`, with no I/O (159).
    - `re_export_map` is not consulted, so `export * from` barrels create no edges. `..` segments are not normalized. [CR]
  - `reverse_deps` is stored once at `initialize()` (watch.rs:123) and never rebuilt.
    - The struct doc (watch.rs:41-46) states it "does not track incremental import-graph edits within a session".
    - Add or remove imports and the graph stays stale until a new session.
  - `IncrementalUpdate.affected_files` returns the affected file set.
  
  ### Caches and invalidation
  | Cache | Key | Invalidated by |
  |---|---|---|
  | `DtsCache` (cache.rs:92-96, `DashMap<CacheKey,SourceData>`) | `(path, FxHasher content hash)` (51-61) | A different content hash creates a new key. |
  | `source_cache` | file path | Overwritten each update. Never read anywhere else (grep shows only inserts). |
  | `component_cache` | display name, or `"Name (path)"` | Only the changed file's own entries are evicted. |
  | `diagnostics` | changed file path | Replaced (not appended) on each `update_file`. |
  | `named_types` `Mutex<Arc<NamedTypeIndex>>` | `(file, name)` | Patched per file. |
  
  DTS cache details:
  - It is used only for `.d.ts` files, in `extract_with_global` (pipeline/mod.rs:273, 299-320) and `merge_cached_dts_file` (531-548).
  - It has the same key and the same cache handle in the cold path only. `update_file` bypasses it entirely.
  - The manifest has only `schema` and `entry_count` (cache.rs:206-210). There is no extractor or crate version, so extractor logic changes without a `SourceData` shape change do not invalidate.
  - `insert` (151-162) never removes older-hash entries for the same path.
  - When 5000 entries are reached, it evicts the first 100 by map iteration order.
  - Save is atomic for the data file (temp + rename). The manifest is written non-atomically afterwards.
  
  Per-call rebuild costs in `update_file`:
  - `ResolutionContext::build` (resolver/mod.rs:178-219) rebuilds the following on every call:
    - `ImportResolutionMap`
    - enum and const-array indexes
    - a new `oxc_resolver::Resolver` (so its filesystem cache is discarded)
    - a tsconfig-paths read (line 184)
  - Only `ambient_global_files` (a OnceLock) and `named_types` are kept incrementally.
  
  ### History of "stale" bugs (comments, tests and commits)
  - **1960470** (2026-07-08): `snapshot()` hardcoded empty diagnostics. A per-file diagnostics `DashMap` was added, "replaced, not appended… so a fixed file's stale diagnostic doesn't linger" (watch.rs:59-61).

    - CLAUDE.md cites it: "a stale-by-one-edit watch mode".
  - **53c77ad** (2026-08-13): `component_cache` staleness, two manifestations.
    - Renamed components left the old key behind. This is tested at watch.rs:1042-1076.
    - A disambiguated component overwrote its peer's bare key, and its own key stayed stale. This is tested at 1087-1144.

  - **d2fcbd7** (2026-08-13): rebuilding `NamedTypeIndex` on every update caused a ~90% `incremental_update` benchmark regression. It now patches incrementally.
  - **7f495a4** (2026-08-13): DTS cache key changed from mtime+size to content hash. The P0-2 same-tick same-size staleness gap is now closed.
  - **Deliberate gap (AC-019)**:
