2. Key Technical Concepts:

- **Module organization**: Rust idiom — cohesive, focused files. The module split IS the enforcement mechanism, not a tool on top of it.
- **`ResolveState` struct**: Replaces `visited: &mut FxHashSet<String>`, `depth: u8`, `diagnostics: &mut Vec<Diagnostic>` threaded through every resolver function. Drops 8-param functions to 4-param. Also carries `needed_specifiers: Vec<NeededSpecifier>` for cross-package resolution.
- **`ScopedKey` newtype**: Wraps the `format!("{}:{}", path, name)` raw string pattern used as `GlobalSourceData` map keys. Single canonical constructor, type-checked.
- **`FxHashSet<CompactString>` for visited**: `CompactString` is already in workspace; most type names fit inline (≤24 bytes). Eliminates heap alloc per visited type.
- **`PropType` serde**: Hand-rolled via `serde_json::Value` intermediary to avoid 19-minute serde derive compile. Root cause was serde 1.x recursion bug, now fixed in recent versions. `Array(Box<PropType>)` already done; `Vec<PropType>` doesn't recurse the macro. Attempt `#[derive(Serialize, Deserialize)]` — if it works, remove 200-line hand-roll.
- **IO error propagation**: `fs::read_to_string(path).unwrap_or_default()` silently drops permission errors. Must emit `Diagnostic::io_error` instead.
- **Silent IO = quality failure**: A file permission error produces 0 components with no diagnostic — unacceptable.
- **Visibility model**: All 8 modules currently `pub mod`. Real public API is only `pipeline`, output types, `react_types`. Everything else should be `pub(crate)`.
- **Cross-package resolution**: Import-guided, demand-driven, multi-pass. `ResolveState.needed_specifiers` feeds a loop in `pipeline/resolve.rs`. All machinery (oxc_resolver, DtsCache, parse_file, GlobalSourceData::merge) already exists — ~40 lines of wiring.
- **LLVM match vs phf**: For <150 arms, LLVM jump-table optimization on string matches is faster than phf. `known.rs` match is idiomatic and should stay.
- **`cargo-semver-checks`**: The one tool that actually matters — after visibility cleanup, prevents accidental API surface expansion in releases.
- **`cargo-deny`**: License policy + OXC version skew prevention (all OXC crates must be 0.135.x).
- **`proptest`**: Property-based testing for the parser. Assert `parse_file` never panics on arbitrary input. Table stakes for an open-source parser.
- **`insta` snapshot tests**: Must be added BEFORE refactor starts. Safety net locking output format.
- **`divan` benchmarks**: Baseline before behavioral changes to catch perf regressions.
