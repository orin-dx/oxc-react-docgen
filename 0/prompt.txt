## 5. Problem Solving

**R3 depth-in-state decision**: The architecture doc envisioned depth inside `ResolveState`, but incrementing/restoring it through recursive calls with mutable reference sharing is tricky without RAII guards. Decision: keep `depth: u8` as a separate value parameter alongside `state: &mut ResolveState`. This reduces the param count from 3 to 2 while avoiding complexity.

**R9 PropType derive impossibility**: `#[serde(tag = "kind")]` internally tagged representation doesn't support tuple/newtype variants. `#[serde(tag = "kind", content = "0")]` adjacently tagged would work for newtypes (preserving `"0"` field name) but wraps struct variants in a `"0"` object — breaking current format for `Named`, `EventHandler`, `Ref`, `HtmlAttributes`, `LiteralUnion`, `Opaque`. Accepted this as a known limitation; hand-rolled serde stays.

**Agent delegation for large mechanical transforms**: R3 (17 function signatures), R4 (resolver split), R5 (extractor split), R6-part2 (pipeline split), R7 (CLI split) were all delegated to spawned agents given the size of the changes. Each agent was given precise instructions about target structure, import patterns, and compile verification.
