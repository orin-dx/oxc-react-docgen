2. Key Technical Concepts:

- **RDT (react-docgen-typescript) output shape**: `ExtractionOutput { components, enums, diagnostics, stats }`; `ComponentEntry { displayName, filePath, description, props, inheritance, notableInherited, discriminantProp, composes, tags, methods }`; `ParsedProp { name, type, required, defaultValue, description, tags, parent, declarations }`
- **PropType tagged union**: 21 kinds — `string`, `number`, `boolean`, `null`, `unknown`, `undefined`, `never`, `void`, `any`, `reactNode`, `cssProperties`, `elementType`, `sxProps`, `stringLiteral`, `numberLiteral`, `boolLiteral`, `union`, `intersection`, `array`, `tuple`, `object`, `named`, `eventHandler`, `ref`, `htmlAttributes`, `literalUnion`, `opaque`
- **CollectedType vs PropType**: `CollectedType` (raw AST from extractor) → `PropType` (resolved semantic type, tagged union)
- **`sxProps` known-pattern shortcut**: Fires in `resolve_named` Step 5 (fallback) ONLY when type cannot be resolved from source — not when `SxProps<T>` is defined locally in fixture
- **`CollectedType::Raw` resolver**: Source-text fallback for tuple elements; now recognizes TypeScript primitive keywords before treating as Named refs
- **Tuple element bug**: `ts_tuple_element_to_collected` uses `CollectedType::Raw(source_text)` for plain type elements; `Raw("number")` was resolving to `Named{number}` not `PropType::Number`
- **Component-level JSDoc tags**: Collected from JSDoc on the component variable declaration (not interface), stored in `ComponentMapping.tags`, flow to `ComponentEntry.tags` via `mapping.tags.clone()` at `resolver/mod.rs:155`
- **JSDoc `@default` conflict**: Code default always wins; if both exist and differ, emits `JsDocDefaultMismatch` Info diagnostic and uses code value
- **`extract_jsdoc_tags`**: Generic — stores any `@tagname value` pair verbatim; special-cased only for `@param`
- **`resolve_function_type`**: 0 params → `EventHandler{void}`, 1 param → `EventHandler{event_type}`, ≥2 params → `Opaque{ConditionalType}` (wrong reason, param names lost)
- **`classify_type_alias` BUG**: No `TSTypeLiteral` arm — `type X = { field: string }` object-literal aliases are silently dropped (never stored), making all references to them resolve as `Named` with UNRESOLVABLE_IMPORT
- **`Pick<LibType, Keys>`**: Only works over project-source interfaces; `Pick<ButtonHTMLAttributes<...>, Keys>` → 0 props (HTML attrs not in source)
- **Namespace compound components**: `ReExportNamespace` captured in `data.exports` but **never consumed** in pipeline — compound naming never produced
- **Generic type params**: `resolve_interface_chain` takes `_type_args: &[String]` but ignores it (underscore-prefixed, never used) — T never substituted
- **`ComponentPropsWithoutRef<typeof Primitive.button>`**: Only `StringLiteral` arg produces `HtmlAttributes`; `typeof X` arg → `Named`, all HTML props lost (critical real Radix gap)
- **Dead code**: `func.rs:34-37` render-prop detection unreachable (prefix mismatch); `OpaqueReason::UnresolvableImport` and `OpaqueReason::PandaCodegenMissing` never constructed
- **`OXC parse`**: Pure structural extraction, no type-checking pass; OXC 0.135
- **DTS cache**: `node_modules/.cache/oxc-react-docgen/` using msgpack + atomic write, mtime+size keyed
- **CSS-in-JS alternatives**: PandaCSS `RecipeVariantProps`/`defineRecipe` (covered), vanilla-extract, Tailwind, Stitches — CSS alternatives question is pending

4. Errors and Fixes:

**Bug: Tuple elements resolved as `Named` instead of primitives:**
- Symptom: `[number, number]` produced `{ kind: "named", name: "number" }` in snapshot
- Root cause: `ts_tuple_element_to_collected` in extractor falls through to `CollectedType::Raw(source_text)` for all plain type elements. The `Raw` resolver saw `"number"` as a plain identifier → `Named`
- Fix: Added `match trimmed { "string" | "number" | "boolean" | ... => return PropType::Xxx, _ => {} }` in `collected.rs` `Raw` handler before the identifier fallback

**Issue: SizeTokens mapped type alias didn't produce `opaque`:**
- Attempted: `type SizeTokens = { [K in 'sm'|'md'|'lg']: string }; prop?: SizeTokens`
- Result: `Named{SizeTokens}` with UNRESOLVABLE_IMPORT diagnostic (not `opaque`)
- Reason: Mapped type aliases are NOT stored in `CollectedTypeAlias` (no variant for them); references to them fall through to Step 7 in `resolve_named` → `Named` + diagnostic
- Fix: Replaced with inline conditional type `string extends 'a' ? 'yes' : 'no'` which correctly produces `opaque{conditionalType}`

**Issue: Avatar not extracted from `React.memo<AvatarProps>(({ ... }) => ...)`:**
- Symptom: filesParsed=2 but 0 components from memo fixture
- Root cause: Generic type arg `<AvatarProps>` on `React.memo` is not used by extractor for props detection; destructured `({ name, src, size })` without explicit type annotation is untyped
- Fix: Changed to `React.memo(function Avatar(props: AvatarProps) { ... })` — explicit `props: AvatarProps` annotation is what the extractor looks for
